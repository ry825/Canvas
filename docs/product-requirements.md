# プロダクト要求定義書 (Product Requirements Document)

## 1. プロダクト概要

### 1.1 名称

**CanvasDoc（仮称）** - 自由配置から読みやすいHTMLを作る文書エディタ

### 1.2 プロダクトコンセプト

- **自由に考え、構造的にまとめる**: 無限キャンバス上で文章、画像、表、図を組み合わせながら、章・節のある文書として整理できる。
- **編集レイアウトと閲覧レイアウトの両立**: 編集中は自由配置を提供し、出力時は明示したブロック順とレイアウトに従ってレスポンシブ文書へ変換する。
- **ローカルで完結する可搬性**: アカウント登録を必要とせず、編集データとHTML成果物をファイルとして保存・共有できる。

### 1.3 プロダクトビジョン

技術者や業務担当者が、文章中心のエディタと作図ツールを行き来せず、考えるところから配布可能な文書を完成させられる環境を提供する。編集時の空間的な自由さを維持しながら、読み手には端末を問わず理解しやすいHTML文書を届ける。HTMLやCSSの知識がなくても、説明力のある技術・業務文書を個人のブラウザだけで作成できる状態を目指す。

### 1.4 目的

- 文章、画像、表、図解を一つの編集環境で組み立てられるようにする。
- 自由配置された内容から、読み順が明確なレスポンシブHTMLを生成する。
- 文書データをローカルで安全に保存・復元できるようにする。
- 初見のユーザーが短時間で基本文書を作成し、HTMLとして書き出せる操作性を実現する。

## 2. 背景と課題

一般的な文書エディタは文章の連続的な編集に優れる一方、複雑な図解や空間的なレイアウトには制約がある。ホワイトボードや作図ツールは自由配置に優れるが、章・節、読み順、モバイル表示を備えた文書の配布には向いていない。また、Webオーサリングツールは柔軟だが、技術・業務文書の作成者にHTML/CSSやWebレイアウトの知識を要求しやすい。

CanvasDocは、編集時の自由配置と、出力時の意味的な文書構造を分離して扱うことでこの課題を解決する。ユーザーはキャンバスで考えを組み立てつつ、章・節ツリーと出力ブロック順によって読み手向けの構造を明示する。

## 3. ターゲットユーザー

### 3.1 プライマリーペルソナ

**佐藤葵（34歳、社内システムエンジニア、実務経験10年）**

- 要件整理、設計概要、運用手順、障害報告などを日常的に作成する。
- Windows PCでブラウザ、Microsoft Office、Markdown、作図ツールを利用する。
- 文書内に画面キャプチャ、表、処理フロー、注意事項を頻繁に配置する。
- Wordでは図の配置が崩れやすく、作図ツールでは長文や章構成を管理しにくいと感じている。
- HTMLやCSSを直接編集せず、ブラウザで閲覧できる成果物を作りたい。
- 日中に情報を収集してキャンバスへ配置し、章・節ごとに整理した後、レビュー用HTMLをローカルへ書き出す。

### 3.2 セカンダリーユーザー

- 業務手順書や研修資料を作成するバックオフィス担当者
- 調査結果や提案を図解付きでまとめる個人事業主
- Markdownだけでは表現しにくい技術解説を作成する開発者

## 4. ユーザー価値

- 複数ツール間のコピー、貼り付け、レイアウト調整を減らせる。
- 編集中は図解と文章の関係を空間的に考えられる。
- 読み順を明示できるため、自由配置でもアクセシブルなHTMLを生成できる。
- 単一HTMLを選べば、ファイル一つでオフライン共有できる。
- 編集データがローカルに留まり、機密性のある社内文書にも利用しやすい。

## 5. 成功指標 (KPI)

初期版は外部分析基盤を持たないため、テストシナリオ、ユーザビリティテスト、生成物の自動検証で測定する。

### 5.1 プライマリーKPI

- **文書作成完遂率**: 初回利用者5名以上によるテストで、4名以上が15分以内に「2節、本文、画像、表、図形を含む文書」を作成し、単一HTMLとして出力できること（MVP受け入れ時）。
- **出力再現成功率**: 標準テスト文書20件の全件が、最新安定版のChrome、Edge、Firefoxで欠落なく表示されること（MVP受け入れ時）。
- **保存復元成功率**: 標準テスト文書20件について、保存・再読み込み後の文書構造、要素内容、画像、配置、出力順の一致率が100%であること（MVP受け入れ時）。

### 5.2 セカンダリーKPI

- **基本操作習得時間**: 初回利用者の中央値が10分以内で、要素追加、移動、編集、Undo、保存を完了できること。
- **レスポンシブ適合率**: 標準テスト文書20件が、幅360px、768px、1440pxで横方向の本文スクロールを発生させないこと。例外はユーザーが明示的に固定幅指定した表のみとする。
- **重大データ損失件数**: 自動保存、明示保存、読み込みの受け入れテスト中に0件であること。

## 6. 機能要件

### 6.1 コア機能 (MVP)

#### FR-01 文書と章・節の管理

**ユーザーストーリー**:  
技術・業務文書の作成者として、長い文書を整理して読み順を管理するために、章・節を階層構造で作成・並べ替えたい。

**受け入れ条件**:

- [ ] 新規文書を作成し、タイトルを設定できる。
- [ ] 章と節を追加、名称変更、削除できる。
- [ ] 章・節をドラッグ操作または移動操作で並べ替えられる。
- [ ] 削除操作の前に確認を表示し、確認後のみ配下の内容を削除する。
- [ ] HTML出力時の章・節の順序が、文書ツリーの順序と一致する。

**優先度**: P0（必須）

#### FR-02 無限キャンバスの操作

**ユーザーストーリー**:  
文書作成者として、考えを空間的に整理するために、節ごとのキャンバス上へ要素を自由に配置したい。

**受け入れ条件**:

- [ ] 各節に独立したキャンバスが存在する。
- [ ] パン、ズーム、要素の選択、移動、リサイズができる。
- [ ] 複数要素を選択し、一括移動、複製、削除できる。
- [ ] 左揃え、中央揃え、右揃え、上揃え、上下中央揃え、下揃えを実行できる。
- [ ] コピー、切り取り、貼り付けおよび最大100操作のUndo/Redoができる。
- [ ] 節を切り替えて戻った際、表示位置とズーム倍率が復元される。

**優先度**: P0（必須）

#### FR-03 文書要素の作成と編集

**ユーザーストーリー**:  
文書作成者として、説明に必要な情報を一つの文書へ集約するために、文章、画像、表、図形、関係線を配置・編集したい。

**受け入れ条件**:

- [ ] 見出し、リッチテキスト、画像、表、図形、コネクタ、リンクの7種類を追加できる。
- [ ] リッチテキストで段落、太字、斜体、箇条書き、番号付きリスト、インラインリンクを編集できる。
- [ ] 画像をファイル選択、ドラッグ＆ドロップ、クリップボード貼り付けで追加できる。
- [ ] PNG、JPEG、WebP、GIF形式の画像を扱い、未対応形式は理由を示して拒否する。
- [ ] 表の行列追加・削除、セル内容編集、ヘッダー行指定ができる。
- [ ] 矩形、角丸矩形、楕円、ひし形の図形を作成し、塗り、線、内部テキストを設定できる。
- [ ] コネクタは2要素へ接続でき、接続先の移動に追従する。
- [ ] 外部リンクにはURLと表示ラベルを設定できる。

**優先度**: P0（必須）

#### FR-04 要素プロパティとスタイル

**ユーザーストーリー**:  
文書作成者として、情報の重要度と関係を視覚的に伝えるために、要素の見た目を調整したい。

**受け入れ条件**:

- [ ] 選択要素に応じたプロパティをサイドペインへ表示する。
- [ ] テキスト色、背景色、境界線、文字サイズ、文字揃えを設定できる。
- [ ] 要素の幅、高さ、キャンバス座標を数値でも確認・変更できる。
- [ ] 複数選択時は共通して変更可能なプロパティのみ表示する。
- [ ] 操作結果がキャンバスへ即時反映される。

**優先度**: P0（必須）

#### FR-05 HTML用の読み順とレイアウト管理

**ユーザーストーリー**:  
文書作成者として、自由配置した内容を端末に依存せず読みやすくするために、HTMLでの読み順と配置方法を明示したい。

**受け入れ条件**:

- [ ] 各節にHTML出力対象ブロックの一覧を表示できる。
- [ ] ブロックをドラッグ操作または移動操作で並べ替えられる。
- [ ] 各要素をHTML出力へ含めるか除外するか設定できる。
- [ ] レイアウトとして「全幅」「左右横並び」「段組内」を指定できる。
- [ ] 横並び・段組では対象要素をグループ化し、グループ内の順序を設定できる。
- [ ] 360px幅では横並びと段組が読み順に従った縦並びへ切り替わる。
- [ ] キャンバス上の座標はHTMLの読み順を自動変更しない。

**優先度**: P0（必須）

#### FR-06 ローカル保存・読み込み

**ユーザーストーリー**:  
個人利用者として、作業を継続し別の環境へ持ち運ぶために、編集可能な文書をローカルファイルとして保存・読み込みたい。

**受け入れ条件**:

- [ ] 文書をバージョン番号付きのJSONファイルとして保存できる。
- [ ] 保存ファイルに章・節、全要素、スタイル、座標、読み順、レイアウト指定、画像データが含まれる。
- [ ] 対応するJSONファイルを読み込むと保存時の状態を復元できる。
- [ ] 不正または未対応バージョンのファイルを読み込んだ場合、既存文書を変更せずエラー理由を表示する。
- [ ] 読み込み前に未保存の変更がある場合、確認を表示する。

**優先度**: P0（必須）

#### FR-07 自動保存と復元

**ユーザーストーリー**:  
文書作成者として、ブラウザの誤終了による作業損失を防ぐために、作業内容を自動保存して復元したい。

**受け入れ条件**:

- [ ] 変更後5秒以内にブラウザ内ストレージへ自動保存する。
- [ ] 再起動時に自動保存データが存在する場合、復元または破棄を選択できる。
- [ ] 自動保存失敗時に作業を継続したまま警告を表示する。
- [ ] 明示的なファイル保存が成功した日時を画面上で確認できる。

**優先度**: P0（必須）

#### FR-08 単一HTMLエクスポート

**ユーザーストーリー**:  
文書作成者として、成果物を簡単に共有するために、画像とスタイルを含む単一HTMLファイルを書き出したい。

**受け入れ条件**:

- [ ] CSSと画像を埋め込んだHTMLファイルを生成できる。
- [ ] 生成ファイルはネットワーク接続なしで表示できる。
- [ ] 章・節、見出し、段落、リスト、figure、table、リンクを意味的なHTML要素として出力する。
- [ ] 図形とコネクタをSVGとして出力する。
- [ ] 文書ツリーとブロック一覧で指定した読み順をDOM順序へ反映する。
- [ ] JavaScriptを無効にしても本文、画像、表、図が閲覧できる。
- [ ] 出力前に未対応または欠落している内容を検証し、問題箇所を表示する。

**優先度**: P0（必須）

#### FR-09 フォルダ形式エクスポート

**ユーザーストーリー**:  
文書作成者として、Webサーバーへの配置やアセット差し替えを行うために、HTML、CSS、画像を分離して書き出したい。

**受け入れ条件**:

- [ ] `index.html`、`styles.css`、`assets/`を含むZIPファイルを生成できる。
- [ ] ZIP展開後の`index.html`を開くとネットワーク接続なしで表示できる。
- [ ] アセット名の重複を防ぎ、HTMLから相対パスで参照する。
- [ ] 単一HTML出力と同じ文書構造、読み順、表示ルールを使用する。

**優先度**: P0（必須）

### 6.2 初期リリース後の重要機能

#### FR-10 キーボード操作の拡充

**ユーザーストーリー**:  
頻繁に文書を作成する利用者として、編集速度を上げるために、要素追加や整列をキーボードで操作したい。

**受け入れ条件**:

- [ ] 主要操作のショートカット一覧をアプリ内で確認できる。
- [ ] キーボードのみで要素選択、移動、編集、削除、Undo/Redoを実行できる。

**優先度**: P1（重要）

#### FR-11 文書テーマ

**ユーザーストーリー**:  
文書作成者として、成果物の見た目を一貫させるために、文書全体の色と書体をまとめて設定したい。

**受け入れ条件**:

- [ ] 文書全体の基本書体、本文色、背景色、アクセント色を設定できる。
- [ ] 設定が編集画面と両方のHTML出力へ反映される。

**優先度**: P1（重要）

- PDF・印刷向け出力
- Excel/CSVデータの取り込みと高度な表編集
- クラウド保存、共有リンク、コメント、共同編集

**優先度**: P2（将来検討）

## 7. データと入出力要件

### 7.1 編集文書ファイル

- 形式はUTF-8のJSONとする。
- ルートに`schemaVersion`、文書メタデータ、章・節ツリー、要素、HTML出力設定、テーマ、画像アセットを保持する。
- 各章、節、要素には文書内で一意かつ保存後も安定するIDを付与する。
- 画像はMVPではData URLまたは同等の埋め込み表現で保持し、外部ファイルへの絶対パスへ依存しない。
- 未知の追加フィールドは可能な限り無視し、必須フィールドの欠落は読み込みエラーとする。

### 7.2 HTML出力

- UTF-8で生成し、`lang="ja"`を既定値とする。
- 文書タイトルを`title`およびページ内の最上位見出しへ反映する。
- 外部CDN、外部フォント、外部スクリプトには依存しない。
- ユーザー入力はエスケープまたは許可リスト方式でサニタイズし、任意スクリプトを出力しない。
- 外部リンクはユーザーが設定したURLのみを使用し、新規タブ表示時は`rel="noopener noreferrer"`を付与する。

## 8. 非機能要件

### 8.1 パフォーマンス

- 推奨環境において、要素500個、節50個、埋め込み画像合計50MBまでの標準文書を5秒以内に読み込む。
- 同条件でパン、ズーム、単一要素の移動中に、操作フレームの95%以上を30fps以上で描画する。
- Undo/Redo、節切り替え、プロパティ変更の画面反映を通常操作時300ms以内に開始する。
- 50MBの標準文書について、単一HTMLまたはZIPの生成を10秒以内に完了する。

### 8.2 ユーザビリティ

- 初回利用者の80%以上が、説明者の介入なしで15分以内にKPIの標準文書を作成・出力できる。
- 保存状態、自動保存状態、選択中の節、選択中の要素を常時視認できる。
- 削除、読み込み、新規作成など未保存内容を失う操作には確認を表示する。
- エラー表示には原因、影響、ユーザーが取れる次の操作を含める。

### 8.3 信頼性

- 自動保存処理は編集操作を妨げず、失敗してもメモリ上の編集中データを保持する。
- 読み込み検証に失敗した場合、現在開いている文書を変更しない。
- エクスポート失敗時に編集中データを変更しない。
- 同一の入力文書とアプリバージョンから、意味的に同一のHTML構造を生成する。

### 8.4 セキュリティとプライバシー

- MVPは文書内容を外部サーバーへ送信しない。
- テレメトリーおよび外部分析サービスを既定で使用しない。
- 読み込んだリッチテキストとリンクをサニタイズし、スクリプト、イベントハンドラー、危険なURLスキームを除去する。
- 生成HTMLに編集アプリ固有のローカルパスやブラウザ内ストレージ情報を含めない。
- ZIP内のファイル名を正規化し、パストラバーサルを発生させない。

### 8.5 対応環境

- Windows 11上の最新安定版ChromeおよびEdgeを正式対応とする。
- 最新安定版Firefoxを閲覧・基本編集の互換対象とする。
- 生成HTMLは最新安定版のChrome、Edge、Firefox、Safariで閲覧可能とする。
- 編集UIは最小幅1024pxを対象とし、生成HTMLは幅360px以上に対応する。

### 8.6 アクセシビリティ

- 編集UIの主要操作に明確なラベルとフォーカス表示を提供する。
- 生成HTMLは見出し階層、文書ランドマーク、表見出し、画像代替テキストを表現できる。
- 画像追加時は代替テキストを任意入力でき、未入力の場合はエクスポート検証で警告する。
- 生成HTMLのテキストと背景の既定配色はWCAG 2.2 AAのコントラスト基準を満たす。

## 9. スコープ外

- ユーザー登録、認証、課金
- サーバーへの文書保存、共有リンク、リアルタイム共同編集
- PDF、Word、PowerPointへの直接出力
- Excelファイルの取り込み、数式計算、ピボットテーブル、高度なセル結合
- 動画、音声、3Dモデル、実行可能コードの埋め込み
- ユーザーが記述したJavaScriptの実行または出力
- テンプレートマーケット、プラグイン、拡張機能API
- モバイル端末での編集最適化

## 10. リスクと対策

| リスク | 影響 | 対策 |
|---|---|---|
| 自由配置とレスポンシブHTMLの見た目が一致しない | 出力結果が期待と異なる | キャンバス座標とHTML用レイアウトを明確に分離し、出力プレビューと検証警告を提供する |
| 大量画像でブラウザメモリを圧迫する | 編集や保存が失敗する | 使用量を表示し、推奨上限50MBを超える前に警告する |
| リッチテキストから危険なHTMLが混入する | 生成HTMLでスクリプトが実行される | 許可リスト方式のサニタイズとセキュリティテストを実施する |
| ブラウザストレージの消去で自動保存が失われる | 作業データが失われる | 自動保存は補助と明記し、明示的なJSON保存状態を常時表示する |
| 複雑な図形・線のレスポンシブ変換が破綻する | 図解が読みにくい | 図形グループはSVGビューボックス内で比率を保って縮小する |

## 11. MVP受け入れ基準

- P0機能の全受け入れ条件を満たしている。
- KPIに定義した文書作成完遂率、出力再現成功率、保存復元成功率を満たしている。
- 標準テスト文書が対応ブラウザと対象画面幅で閲覧できる。
- 重大度「高」の既知不具合が0件である。
- ローカル保存、自動保存、単一HTML、ZIP出力の失敗時に編集中データが失われない。
- セキュリティ検証で、スクリプト挿入、危険なURL、ZIPパストラバーサルが成立しない。

## 12. 前提と未確定事項

### 前提

- 初期版は個人のローカル利用を対象とする。
- 編集時の自由配置より、生成HTMLの読み順とレスポンシブ性を優先する。
- HTMLの読み順とレイアウトはユーザーが明示的に管理し、キャンバス座標から自動推測しない。
- プロダクト名「CanvasDoc」は正式名称決定までの仮称とする。

### 今後、機能設計で確定する事項

- 編集画面の詳細な画面構成と操作フロー
- JSONスキーマの具体的なフィールド定義とマイグレーション規則
- 各要素の既定スタイルとテーマトークン
- 図形グループとコネクタをHTML用SVGへ変換する詳細規則
- 自動保存に使用するブラウザストレージ方式と容量管理
