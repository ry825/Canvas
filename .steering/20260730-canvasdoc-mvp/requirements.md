# CanvasDoc MVP 実装要求

## 概要

技術・業務文書を無限キャンバス上で編集し、編集可能なJSON、単一HTML、HTML＋アセットZIPとしてローカル出力できるブラウザアプリを実装する。PRDのP0要件FR-01〜FR-09をすべて満たすことを、この作業計画の完了条件とする。

## 背景

文章中心の文書エディタは図解の自由度が低く、ホワイトボードや作図ツールは章・節やレスポンシブな読み順を持つ成果物の作成に向かない。CanvasDocは、編集用の自由配置と閲覧用の意味的レイアウトを分離し、両者を一つのローカル完結型アプリで扱う。

## 実装対象

### 1. アプリケーション基盤

- React、TypeScript、Viteを使った静的SPAを構築する。
- UI、Application、Domain、Infrastructureの依存境界をディレクトリと静的検査で強制する。
- Formatter、Lint、型チェック、Unit/Integration/E2E、ビルドを標準コマンドで実行可能にする。

### 2. 文書モデルと編集履歴

- 文書、章、節、7種類の要素、画像アセット、HTML出力レイアウトを型付きモデルとして実装する。
- 章・節と要素の追加、編集、削除、移動、整列、複製をCommandとして実装する。
- 最大100操作のUndo/Redoと、複数モデル更新の原子性を保証する。

### 3. 文書編集UI

- 上部ツールバー、左の文書ツリー、中央の無限キャンバス、右のプロパティ・出力アウトライン・プレビュー、下部ステータスバーを実装する。
- パン、ズーム、選択、複数選択、移動、リサイズ、整列、コピー、切り取り、貼り付けを提供する。
- 見出し、リッチテキスト、画像、表、図形、コネクタ、リンクを作成・編集できるようにする。

### 4. ローカル保存と復元

- `schemaVersion: 1`のCanvasDoc JSONを保存・読み込みできるようにする。
- 外部JSONをZodとDomain Validatorで検証し、失敗時に現在文書を維持する。
- IndexedDBへ変更後5秒以内に自動保存し、起動時に復元または破棄を選べるようにする。

### 5. レスポンシブHTML出力

- キャンバスの描画順とは独立したHTML出力順とレイアウトグループを編集できるようにする。
- 意味的なHTML、CSS、インラインSVG、画像から共通の`ExportBundle`を生成する。
- CSSと画像を埋め込んだ単一HTML、および`index.html`、`styles.css`、`assets/`を含むZIPを出力する。
- 生成物はJavaScriptおよびネットワーク接続なしで閲覧可能にする。

### 6. 品質・セキュリティ・性能

- リッチテキスト、URL、SVG、JSON、ZIPパスに対する攻撃入力を拒否または無害化する。
- 編集UIの主要操作と生成HTMLへアクセシビリティ要件を適用する。
- 50節、500要素、画像合計50MBの標準文書で性能要件を検証する。
- Chrome、Edge、Firefoxで編集・出力を確認し、生成HTMLをWebKitでも確認する。

## 受け入れ条件

### アプリケーション基盤

- [ ] `npm ci`後に開発サーバー、型チェック、Lint、テスト、production buildを実行できる。
- [ ] Domainから外側のレイヤーへのimportと循環依存をCIで検出できる。
- [ ] production buildが外部CDN、外部フォント、サーバーAPIへ依存しない。

### 文書と章・節

- [ ] 文書タイトル、章、節を作成、名称変更、削除、並べ替えできる。
- [ ] 章・節の削除前に確認が表示され、キャンセル時は状態が変化しない。
- [ ] 文書ツリーの順序がHTMLの章・節のDOM順と一致する。

### キャンバス編集

- [ ] 各節が独立した要素、ビューポート、出力レイアウトを持つ。
- [ ] 0.1〜4倍のズーム、パン、単一・複数選択、移動、リサイズ、整列ができる。
- [ ] コピー、切り取り、貼り付け、複製、削除を実行できる。
- [ ] 最大100操作のUndo/Redoができ、複数要素操作を一度に戻せる。
- [ ] 節を切り替えて戻るとパン位置とズーム率が復元される。

### 文書要素

- [ ] 見出し、リッチテキスト、画像、表、図形、コネクタ、リンクを追加・編集できる。
- [ ] PNG、JPEG、WebP、GIFをファイル選択、ドラッグ＆ドロップ、クリップボードから追加できる。
- [ ] 未対応画像形式と20MB超の単一画像を理由付きで拒否する。
- [ ] 表の行列追加・削除、セル編集、ヘッダー行指定ができる。
- [ ] コネクタが同じ節の2要素を結び、接続先移動に追従する。

### 保存・復元

- [ ] JSON保存後に再読み込みすると、文書構造、要素、画像、座標、描画順、出力順、ビューポートが一致する。
- [ ] 不正JSON、参照不整合、未対応上位バージョンを読み込んでも、現在文書が変化しない。
- [ ] 変更後5秒以内にIndexedDBへ自動保存が開始される。
- [ ] 起動時に自動保存候補の復元または破棄を選択できる。
- [ ] 自動保存容量不足時も編集を継続し、JSON明示保存を案内する。

### HTML・ZIP出力

- [ ] 各要素の出力有無と順序を設定できる。
- [ ] 全幅、左右横並び、2〜4段組を設定でき、768px以下では一列へ変換される。
- [ ] 単一HTMLがオフラインで本文、画像、表、リンク、図形、コネクタを表示する。
- [ ] ZIP展開後の`index.html`が相対パスのCSS・画像を使ってオフライン表示される。
- [ ] 単一HTMLとZIPが同じ意味的DOM順とスタイル規則を持つ。
- [ ] 生成HTMLはスクリプトを無効にしても閲覧可能である。

### 品質

- [ ] PRDで定義した保存復元成功率100%と標準出力20件の表示成功率100%を満たす。
- [ ] 360px、768px、1440pxで本文の意図しない横スクロールが発生しない。
- [ ] XSS、危険URL、SVG注入、Prototype Pollution、ZIPパストラバーサルのテストが成功する。
- [ ] 標準性能文書を5秒以内に読み込み、HTML/ZIPを10秒以内に生成する。
- [ ] キャンバス操作フレームの95%以上が30fps以上である。
- [ ] Domain 90%、Application 85%、Infrastructure 80%、UI 70%、全体80%の行カバレッジを満たす。

## 成功指標

- 初回利用者5名以上のうち4名以上が、15分以内に2節、本文、画像、表、図形を含む文書を作成し、単一HTMLへ出力できる。
- 標準文書20件の保存・再読み込み後の意味的状態一致率が100%である。
- 標準文書20件がChrome、Edge、Firefoxで欠落なく表示される。
- 重大度「高」の既知不具合、データ損失、セキュリティ回帰が0件である。

## スコープ外

この作業計画では次を実装しない。

- ログイン、クラウド保存、共有リンク、コメント、共同編集
- PDF、Word、PowerPointへの出力
- Excel/CSV取り込み、数式、ピボット、高度なセル結合
- 文書テンプレート
- AIによる文章・構造・レイアウト生成
- プラグイン機構
- モバイル端末向け編集UI
- Service Workerを使ったPWA・完全オフライン起動
- File System Access APIによる同一ファイルへの上書き保存

## 実装開始の前提

- Node.js 24 LTSとnpm 11.xが使用できること。
- Gitリポジトリが初期化され、`main`と`develop`の運用ブランチが存在すること。
- Pull Request作成時までに、Push可能なリモートリポジトリが設定されていること。
- リモートまたは認証がない場合、対象PRの実装開始前にユーザーへ設定を依頼すること。
- PR-11開始時までに、ユーザーがユーザビリティ試験の参加者5名以上を手配するか、募集を別途調整すること。参加者を確保できない場合、KPI達成判定は行えないためPR-11を開始しない。
